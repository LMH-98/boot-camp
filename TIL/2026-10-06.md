# Spring Boot 첫 수업: REST 컨트롤러 & Spring Data JPA

> 2026-10-06 · STS · Spring Boot 4.1.1 · Java 21 · MariaDB

## ✅ 이것만은 꼭

1. `main()`을 실행하면 **내장 Tomcat**이 같이 뜬다. 클래스는 **시작 클래스의 하위 패키지**에 있어야 인식된다.
2. `@RestController`는 화면(JSP) 대신 **데이터(JSON)** 를 응답한다.
3. `@Entity` 클래스 = 테이블, 객체 하나 = 행 하나. 테이블은 `ddl-auto`가 만들어 준다.
4. `JpaRepository`를 상속한 **인터페이스만 만들면** CRUD 메서드가 생긴다.
5. `save()` 하나로 insert와 update를 모두 한다. **PK가 있으면 update**.
6. 페이지 번호는 **0부터** 시작한다.
7. JPQL은 테이블·컬럼 이름이 아니라 **엔티티·필드 이름**으로 쓴다.
8. `update`·`delete` 쿼리에는 **`@Modifying` + `@Transactional`** 이 필요하다.

## 1. 프로젝트 구조

```

dbtest   Spring Data JPA로 MariaDB 다루기

 ├─ MemoRepository.java          DB 작업용 인터페이스
 ├─ application.properties       DB 접속 · JPA 설정
 └─ MemoRepositoryTests.java     CRUD · 페이징 · 쿼리 테스트
```

## 2. 시작 클래스와 내장 Tomcat

```java
@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

- `main()`을 실행하면 내장 Tomcat이 8080 포트로 뜬다. JSP 때처럼 Tomcat을 따로 설치·연결하지 않는다.
- `@SpringBootApplication`은 **이 클래스가 있는 패키지(`com.fullstack`)와 그 하위 패키지**를 스캔해서 컨트롤러 등을 등록한다.
  → 바깥 패키지에 만든 컨트롤러는 인식되지 않는다 (404).

## 3. @RestController — 데이터만 응답

```java
@RestController
public class SampleController {
    @GetMapping("/hello")
    public String[] hello() {
        return new String[] {"hello", "world"};
    }
}
```

`http://localhost:8080/hello` → `["hello","world"]`

- `@RestController`: 리턴값이 **응답 데이터 그 자체**가 된다. 자바 배열·객체는 JSON으로 자동 변환된다.
- `@Controller`: 리턴값이 **뷰(JSP 등)의 이름**이 된다.
- `@GetMapping("/hello")`: GET 방식 `/hello` 요청을 이 메서드에 연결한다.

## 4. application.properties — DB 연결

```properties
spring.datasource.url=jdbc:mariadb://localhost:3306/bootex
spring.datasource.username=bootex
spring.datasource.password=bootex

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

- DB 정보만 적으면 Spring Boot가 커넥션 풀까지 알아서 만든다.
- DB(`bootex`)와 계정은 미리 만들어 둬야 하지만, **테이블은 JPA가 만든다**.
- `ddl-auto`
  - `create`: 실행할 때마다 테이블을 새로 만든다 → **기존 데이터가 지워진다**
  - `update`: 없는 테이블·컬럼만 추가한다 → 데이터는 유지된다 (수업에서 사용)
- `show-sql`은 실행되는 SQL을 콘솔에 보여 주고, `format_sql`은 그 SQL을 보기 좋게 줄바꿈한다.

> 수업 코드의 `spring.datasource.dbcp2.driver-class-name`은 실제로는 적용되지 않는 키다. 드라이버는 URL을 보고 자동으로 잡히므로 생략해도 되고, 쓴다면 `spring.datasource.driver-class-name`이다.

## 5. Entity — 클래스 = 테이블

```java
@Entity
@Table(name = "tbl_memo")
@Getter @ToString @Builder
@AllArgsConstructor @NoArgsConstructor
public class Memo {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long mno;

    @Column(length = 200, nullable = false)
    private String memoText;
}
```

- `@Entity`: JPA가 관리하는 클래스. 객체 하나가 테이블의 행 하나다.
- `@Id`: 기본키. **모든 엔티티에 반드시 있어야 한다**.
- `@GeneratedValue(IDENTITY)`: 번호는 DB의 auto_increment가 매긴다 → 새로 저장할 때 `mno`는 비워 둔다.
- `@Column`: 컬럼 조건 (`varchar(200) not null`).
- 필드 `memoText`는 컬럼 `memo_text`로 자동 변환된다.
- JPA는 **기본 생성자**가 필요하다 (`@NoArgsConstructor`).

## 6. Repository — 인터페이스만 만들면 끝

```java
public interface MemoRepository extends JpaRepository<Memo, Long> {
}
```

- `JpaRepository<엔티티 타입, PK 타입>`을 상속한다.
- 구현 클래스를 만들지 않아도 Spring Data JPA가 실행할 때 **구현 객체를 자동으로 만들어 주입**한다.

| 작업 | 메서드 | 기억할 점 |
|---|---|---|
| 등록 | `save(entity)` | PK가 비어 있으면 **insert** |
| 수정 | `save(entity)` | PK가 있으면 select로 확인한 뒤 **update** |
| 조회 | `findById(id)` | 결과가 없을 수도 있어서 `Optional`로 준다 |
| 삭제 | `deleteById(id)` | |

```java
memoRepository.save(Memo.builder().memoText("sample1").build());             // insert
memoRepository.save(Memo.builder().mno(100L).memoText("Updated").build());   // update

Optional<Memo> result = memoRepository.findById(100L);
if (result.isPresent()) {
    System.out.println(result.get());
}
```

## 7. 페이징과 정렬

```java
Pageable pageable = PageRequest.of(0, 10, Sort.by("mno").descending());
Page<Memo> result = memoRepository.findAll(pageable);

result.getContent();        // 현재 페이지의 데이터 목록
result.getTotalPages();     // 전체 페이지 수
result.getTotalElements();  // 전체 데이터 수
```

- `PageRequest.of(페이지 번호, 한 페이지 개수, 정렬)` — **페이지 번호는 0부터** 시작한다.
- `Sort.by()`에는 컬럼명이 아니라 **엔티티 필드명**을 쓴다. 정렬 조건 여러 개는 `.and()`로 연결한다.

## 8. 쿼리 메서드 — 메서드 이름이 곧 쿼리

```java
List<Memo> findByMnoBetweenOrderByMnoDesc(Long from, Long to);
// → where mno between ? and ? order by mno desc
```

- 규칙: `findBy` + 필드명 + 조건 키워드 (`Between`, `LessThan`, `Containing`, `OrderBy...Desc` 등)
- 조건이 간단하면 쿼리 메서드, 복잡해지면 `@Query`를 쓴다.

## 9. @Query — JPQL 직접 작성

```java
// 조회: 테이블(tbl_memo)이 아니라 엔티티(Memo)를 대상으로, 별칭 m 사용
@Query("select m from Memo m order by m.mno desc")
List<Memo> getListDesc();

// 수정: :이름 자리에 @Param("이름") 값이 들어간다
@Transactional
@Modifying
@Query("update Memo m set m.memoText = :memoText where m.mno = :mno")
int updateMemoText(@Param("mno") Long mno, @Param("memoText") String memoText);

// 페이징: 전체 개수를 세는 countQuery도 같이 쓴다
@Query(value = "select m from Memo m where m.mno > :mno",
       countQuery = "select count(m) from Memo m where m.mno > :mno")
Page<Memo> getListWithQuery(@Param("mno") Long mno, Pageable pageable);
```

- JPQL은 **엔티티·필드 이름**으로 쓴다 (`Memo`, `memoText` ⭕ / `tbl_memo`, `memo_text` ❌).
- `update`·`delete`에는 `@Modifying`(데이터를 바꾸는 쿼리라는 표시)과 `@Transactional`(트랜잭션 필요)을 붙인다. 리턴값은 바뀐 행 수다.
- 객체를 통째로 넘길 땐 `:#{#param.memoText}`처럼 쓴다.
- 결과가 엔티티 모양이 아니면(일부 컬럼, `current_date` 등) `Object[]`로 받는다.
