## 1. Thymeleaf 기본

### 1-1. 컨트롤러 → 뷰 연결 규칙

```java
@Controller
@RequestMapping("/sample")
public class SampleController {

    @GetMapping("/ex1")
    public void ex1() { }          // 리턴 void → URL 경로가 곧 뷰 이름 → templates/sample/ex1.html

    @GetMapping({"/ex2", "/exLink"})   // 메서드 하나에 URL 여러 개를 매핑할 수 있음
    public void exModel(Model model) {
        model.addAttribute("list", list);  // 뷰에서 ${list}로 꺼내 씀
    }
}
```

- 뷰 파일은 `src/main/resources/templates/` 아래에 두고, 뷰 이름을 쓸 때 `.html`은 붙이지 않는다
- **리턴 타입이 `void`면 요청 URL이 그대로 뷰 이름**이 된다 (`/sample/ex2` → `sample/ex2.html`)
- **`Model`**은 컨트롤러가 뷰로 데이터를 넘길 때 쓰는 상자다. JSP의 `request.setAttribute()`와 같은 역할
- HTML 맨 위에 `xmlns:th="http://www.thymeleaf.org"`를 선언해야 `th:` 속성이 자동완성된다

### 1-2. 자주 쓰는 문법

| 문법 | 용도 | 예시 |
|---|---|---|
| `${...}` | 변수 출력 (Model 값) | `th:text="${dto.first}"` |
| `th:text` | 태그 안에 텍스트로 출력 | `<h1 th:text="${result}"></h1>` |
| `[[...]]` | 태그 없이 바로 출력 (인라인) | `[[${dto}]]` |
| `th:each` | 반복 | `th:each="dto, state : ${list}"` |
| `th:if` / `th:unless` | 조건이 참일 때 / 거짓일 때만 출력 | `th:if="${dto.sno % 5 == 0}"` |
| 삼항 연산자 | if/unless를 한 줄로 | `th:text="${조건} ? ${A} : ${B}"` |
| `th:block` | 화면에 태그를 남기지 않는 블록 | 반복이나 조건만 걸고 싶을 때 |
| `@{...}` | 링크(URL) 만들기 | `th:href="@{/sample/exView}"` |

### 1-3. 반복과 상태 변수 (ex2.html)

```html
<li th:each="dto, state : ${list}">
    <span th:if="${dto.sno % 5 == 0}" th:text="${'-------------' + dto.sno}"></span>
    <span th:unless="${dto.sno % 5 == 0}" th:text="${dto.first}"></span>
    [[${state.index}]] --- [[${dto}]]
</li>
```

- 두 번째 변수 `state`에는 반복 상태가 들어 있다: `index`(0부터), `count`(1부터), `size`, `first`, `last`, `odd`, `even`
- `th:if`와 `th:unless`에 **같은 조건**을 써야 서로 반대로 동작한다

### 1-4. 링크 처리 (exLink.html)

```html
<!-- 쿼리스트링 방식 → /sample/exView?sno=1 -->
<a th:href="@{/sample/exView(sno=${dto.sno})}">...</a>

<!-- 경로 변수 방식 → /sample/exView/1 -->
<a th:href="@{/sample/exView/{sno}(sno=${dto.sno})}">...</a>
```

- 파라미터는 `( )` 안에 쓴다. 경로에 `{sno}`가 있으면 그 자리에 들어가고, 없으면 `?sno=` 형태로 붙는다
- `@{}`는 컨텍스트 경로를 자동으로 붙여 주므로 링크는 항상 `@{}`로 쓰는 습관을 들이자

### 1-5. 리다이렉트 + Flash 속성, `th:inline` (ex3.html)

```java
@GetMapping("/exInline")
public String exInline(RedirectAttributes redirectAttributes) {
    redirectAttributes.addFlashAttribute("result", "success");
    redirectAttributes.addFlashAttribute("dto", dto);
    return "redirect:/sample/ex3";
}
```

```html
<script th:inline="javascript">
    const msg = [[${result}]];   // → "success" (문자열이면 따옴표까지 자동으로 붙음)
    const dto = [[${dto}]];      // → 객체는 JSON 형태로 변환됨
</script>
```

- `redirect:`는 브라우저가 **새 요청**을 보내게 하므로 Model에 넣은 값이 사라진다
- **`addFlashAttribute`**로 넣은 값은 리다이렉트 뒤에 **딱 한 번만** 꺼내 쓸 수 있다 (새로고침하면 사라짐). 등록이나 수정 뒤에 "완료" 메시지를 띄울 때 쓴다
- `th:inline="javascript"`를 쓰면 JS 안에서도 서버 값을 **타입에 맞게** 꺼내 쓸 수 있다

### 1-6. 레이아웃 (공통 화면 재사용)

**레이아웃 파일** (`layout/basic.html`): 페이지마다 바뀌는 부분만 비워 둔다

```html
<th:block th:fragment="setContent(content)">   <!-- content를 파라미터로 받는 조각 -->
    ... 사이드바, 네비게이션 (공통) ...
    <div class="container-fluid">
        <th:block th:replace="${content}"></th:block>   <!-- 여기에 각 페이지 내용이 들어감 -->
    </div>
</th:block>
```

**레이아웃을 쓰는 페이지** (`guestbook/list.html`)

```html
<th:block th:replace="~{/layout/basic :: setContent(~{this::content})}">
    <th:block th:fragment="content">
        <h1>GuestBook List Page</h1>
    </th:block>
</th:block>
```

- `th:fragment`: 재사용할 조각에 이름을 붙인다
- `th:replace="~{파일경로 :: 조각이름}"`: 현재 태그를 그 조각으로 **통째로 바꾼다**
- `~{this::content}`: 이 파일의 `content` 조각을 레이아웃에 파라미터로 넘긴다
- 흐름: list.html의 내용이 basic.html의 `${content}` 자리에 들어가서, 공통 틀과 페이지별 내용이 합쳐진다
- 정적 파일(css, js)은 `static/` 아래에 두고 `th:href="@{/css/...}"`로 연결한다

## 2. Guestbook 프로젝트

### 2-1. 구조

```
controller/  GuestbookController   요청을 받고 뷰를 반환
service/     GuestbookService      인터페이스 + DTO↔Entity 변환용 default 메서드
             GuestbookServiceImpl  실제 로직
repository/  GuestbookRepository   JpaRepository + QuerydslPredicateExecutor
entity/      BaseEntity            등록일/수정일 공통 처리
             Guestbook             방명록 테이블
dto/         GuestbookDTO          화면과 서비스 사이에서 쓰는 데이터
             PageRequestDTO        페이지 요청 정보 (page, size)
             PageResultDTO         페이지 결과 (DTO 리스트)
```

> **흐름**: Controller ↔ (DTO) ↔ Service ↔ (Entity) ↔ Repository ↔ DB
> 엔티티는 DB와 바로 연결된 객체라서 화면까지 가져가지 않는다. 서비스에서 DTO로 바꿔서 넘긴다.

### 2-2. DB 연결 설정 (application.properties)

```properties
spring.datasource.driver-class-name=org.mariadb.jdbc.Driver
spring.datasource.url=jdbc:mariadb://localhost:3306/bootex
spring.datasource.username=bootex
spring.datasource.password=bootex

spring.jpa.hibernate.ddl-auto=update                 # 엔티티를 보고 테이블을 자동으로 생성/변경
spring.jpa.properties.hibernate.format_sql=true      # SQL을 보기 좋게 줄바꿈
spring.jpa.show-sql=true                             # 실행되는 SQL을 콘솔에 출력
```

| ddl-auto 값 | 동작 |
|---|---|
| `create` | 실행할 때마다 테이블을 **지우고 새로 만든다** (데이터가 사라짐) |
| `update` | 엔티티와 테이블이 다를 때만 **바뀐 부분을 반영한다** (데이터 유지) |
| `none` / `validate` | 아무것도 안 함 / 엔티티와 테이블이 맞는지 검사만 함 (운영 환경용) |

### 2-3. BaseEntity: 등록일·수정일 자동 처리 (JPA Auditing)

```java
@MappedSuperclass                                   // 테이블은 만들지 않고, 상속받는 엔티티에 컬럼만 물려줌
@EntityListeners(value = {AuditingEntityListener.class})  // 저장/수정 시점을 감시
@Getter
public class BaseEntity {
    @CreatedDate
    @Column(name = "regDate", updatable = false)    // 수정할 때는 바뀌지 않게
    private LocalDateTime regDate;

    @LastModifiedDate
    @Column(name = "moddate")
    private LocalDateTime modDate;
}
```

```java
@SpringBootApplication
@EnableJpaAuditing      // ★ 이게 없으면 날짜가 null로 들어간다
public class GuestbookApplication { ... }
```

- 여러 테이블에 공통으로 들어가는 컬럼은 부모 클래스로 빼고 `extends BaseEntity`로 상속받는다

### 2-4. Guestbook 엔티티

```java
@Entity
@Getter @Builder @AllArgsConstructor @NoArgsConstructor @ToString
public class Guestbook extends BaseEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)   // MariaDB auto_increment
    private Long gno;

    @Column(length = 100, nullable = false)
    private String title;
    @Column(length = 1500, nullable = false)
    private String content;
    @Column(length = 50, nullable = false)
    private String writer;

    public void changeTitle(String title) { this.title = title; }
    public void changeContent(String content) { this.content = content; }
}
```

- 엔티티에는 `@Setter`를 붙이지 않는다. **바꿔도 되는 필드만 `changeXxx()` 메서드로 열어 두면** 아무 곳에서나 값이 바뀌는 걸 막을 수 있다
- 수정 순서: `findById()`로 꺼내고 → `changeXxx()`로 바꾸고 → `save()`. id가 같으면 UPDATE가 실행되고 `modDate`도 자동으로 갱신된다

### 2-5. QueryDSL: 동적 검색 조건

**왜 쓰나?** "제목이나 내용에 키워드가 들어 있는 글" 같은 조건을 **문자열 SQL이 아니라 자바 코드로** 만들 수 있다. 오타를 컴파일할 때 잡을 수 있고, 상황에 따라 조건을 붙였다 뗐다 할 수 있다.

**설정 포인트 (build.gradle)**
- Boot 4 / Hibernate 7에서는 기존 QueryDSL 대신 **OpenFeign 포크**(`io.github.openfeign.querydsl`)를 쓴다
- 빌드하면 엔티티마다 **Q클래스**(`QGuestbook`)가 `src/main/generated`에 자동으로 생긴다
  → 안 보이면 Gradle `compileJava`를 실행한 뒤 프로젝트를 새로고침

```java
public interface GuestbookRepository
        extends JpaRepository<Guestbook, Long>,          // 기본 CRUD + 페이징
                QuerydslPredicateExecutor<Guestbook> {   // findAll(조건, pageable)을 쓸 수 있게 해줌
}
```

```java
QGuestbook qGuestbook = QGuestbook.guestbook;           // 1. Q클래스 가져오기
BooleanBuilder builder = new BooleanBuilder();          // 2. 조건을 담을 그릇

BooleanExpression exTitle   = qGuestbook.title.contains(keyword);    // 3. 조건 만들기
BooleanExpression exContent = qGuestbook.content.contains(keyword);
builder.and(exTitle.or(exContent));                     // 4. 조건을 조합해서 담기
builder.and(qGuestbook.gno.gt(0L));

Page<Guestbook> result = guestbookRepository.findAll(builder, pageable);  // 5. 실행
```

→ 실행되는 SQL: `WHERE (title LIKE '%1%' OR content LIKE '%1%') AND gno > 0 ORDER BY gno DESC LIMIT 10`

### 2-6. Service: DTO ↔ Entity 변환

```java
public interface GuestbookService {
    Long register(GuestbookDTO dto);
    PageResultDTO<GuestbookDTO, Guestbook> getList(PageRequestDTO dto);

    // 변환 로직을 인터페이스의 default 메서드로 넣어 두면 구현 클래스에서 바로 쓸 수 있음
    default Guestbook dtoToEntity(GuestbookDTO dto) { ... builder로 변환 ... }
    default GuestbookDTO entityToDto(Guestbook entity) { ... builder로 변환 ... }
}
```

```java
@Service
@RequiredArgsConstructor     // final 필드를 생성자로 주입 (@Autowired 대신)
public class GuestbookServiceImpl implements GuestbookService {
    private final GuestbookRepository guestbookRepository;

    @Override
    public Long register(GuestbookDTO dto) {
        Guestbook entity = dtoToEntity(dto);
        guestbookRepository.save(entity);
        return entity.getGno();          // save 후에는 자동 생성된 번호가 들어 있음
    }
}
```

### 2-7. 페이징: PageRequestDTO / PageResultDTO

```
화면 요청(page=1, size=10)
  → PageRequestDTO.getPageable()  → Pageable (JPA는 페이지 번호가 0부터라서 page-1)
  → repository.findAll(pageable)  → Page<Guestbook>
  → PageResultDTO(result, fn)     → List<GuestbookDTO> → 화면으로
```

```java
@Override
public PageResultDTO<GuestbookDTO, Guestbook> getList(PageRequestDTO requestDTO) {
    Pageable pageable = requestDTO.getPageable(Sort.by("gno").descending());
    Page<Guestbook> result = guestbookRepository.findAll(pageable);

    Function<Guestbook, GuestbookDTO> fn = (entity -> entityToDto(entity));
    return new PageResultDTO<>(result, fn);
}
```

```java
@Data
public class PageResultDTO<DTO, EN> {        // 제네릭으로 만들어서 다른 게시판에서도 재사용
    private List<DTO> dtoList;

    public PageResultDTO(Page<EN> result, Function<EN, DTO> fn) {
        dtoList = result.stream().map(fn).collect(Collectors.toList());
    }
}
```

- **`Function<EN, DTO>`**는 "엔티티 하나를 받아서 DTO 하나를 돌려주는 함수"를 객체로 넘기는 것이다
  → `PageResultDTO`는 변환 방법을 몰라도 되고, 넘겨받은 `fn`을 `map()`에 그대로 적용하기만 한다

### 2-8. 테스트 코드 팁

- `@SpringBootTest`와 `@Autowired`로 Repository/Service를 실제 DB에 연결해서 테스트한다
- 더미 데이터 넣기(`insertDummies`)처럼 **한 번만 돌릴 테스트는 실행한 뒤 `@Test`를 주석 처리**한다. 다시 돌리면 데이터 300개가 또 들어간다

## 3. 짚고 넘어갈 것 (오늘 코드 기준)

1. **정렬이 실제로 적용되지 않는다**: `PageRequestDTO.getPageable(Sort sort)`가 `sort`를 받기만 하고 쓰지 않는다.
```java
   return PageRequest.of(page - 1, size, sort);   // sort를 넣어야 gno 내림차순이 적용됨
```
2. **PageRequestDTO에 getter/setter가 없다**: 나중에 컨트롤러에서 `?page=2&size=10`을 받으려면 `@Data`(또는 `@Getter @Setter`)가 필요하다. 또 `@Builder`로 만들면 기본 생성자의 `page=1, size=10`이 적용되지 않으므로, builder로 만들 때는 값을 꼭 넣어야 한다.
3. **properties 키 오타**: `spring.datasource.dbcp2.driver-class-name`이 아니라 `spring.datasource.driver-class-name`이 맞다. 지금은 URL을 보고 드라이버를 자동으로 찾아서 돌아가는 것뿐이다.
4. **뷰 경로 앞의 `/`**: `return "/guestbook/list"`나 `~{/layout/basic ...}`처럼 앞에 `/`를 붙이면 STS에서는 되지만, jar로 배포하면 템플릿을 못 찾을 때가 있다. `"guestbook/list"`, `~{layout/basic ...}`처럼 쓰는 습관을 들이자.
5. `exLink.html`의 `/sample/exView`는 아직 컨트롤러가 없어서 클릭하면 404가 난다. 링크 만드는 연습용이다.
