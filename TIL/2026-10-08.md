## Day N — 방명록 CRUD · 페이징 · 검색

### 오늘 구현한 것
| 기능 | URL | 메서드 |
|---|---|---|
| 목록 (페이징 + 검색) | /guestbook/list | GET |
| 등록 | /guestbook/register | GET / POST |
| 상세 | /guestbook/read | GET |
| 수정 | /guestbook/modify | GET / POST |
| 삭제 | /guestbook/remove | POST |

### 꼭 알고 넘어갈 핵심
**1. 계층 흐름: Controller → Service → Repository**
- Controller는 요청/응답만 담당하고, 실제 로직은 Service가 처리한다.
- 화면과는 DTO로 주고받고, DB와는 Entity로 주고받는다. 변환은 Service에서 한다.

**2. DTO ↔ Entity 변환을 인터페이스 default 메서드로**
- `GuestbookService`에 `dtoToEntity()`, `entityToDto()`를 default로 정의했다.
- 그래서 구현 클래스에서 따로 작성하지 않고 바로 쓸 수 있다.

**3. 페이징: PageRequestDTO / PageResultDTO**
- `PageRequestDTO`: page, size, type, keyword를 받는다. 기본값은 1페이지, 10개.
  - JPA의 페이지는 0부터 시작하므로 `PageRequest.of(page - 1, size, sort)`로 변환한다.
- `PageResultDTO<DTO, EN>`: `Page<Entity>`를 DTO 리스트로 바꾸고 페이지 번호 목록을 계산한다.
  - `tempEnd = ceil(page / 10.0) * 10` → `start = tempEnd - 9`
  - `prev = start > 1`, `next = totalPage > tempEnd`

**4. 검색: Querydsl BooleanBuilder**
- 기본 조건은 `gno > 0`이다.
- type에 t, c, w가 들어 있으면 해당 조건을 **or**로 묶은 뒤, 기본 조건과 **and**로 결합한다.
- Repository에서 `QuerydslPredicateExecutor`를 상속해야 `findAll(predicate, pageable)`를 쓸 수 있다.

**5. 리다이렉트 시 값 전달**
- `addFlashAttribute`: 한 번만 쓰는 값이고 URL에 안 보인다. 등록/삭제 후 모달 메시지에 썼다.
- `addAttribute`: 쿼리 파라미터로 붙는다. 수정 후 page, type, keyword를 유지할 때 썼다.

**6. 검색 조건 유지**
- 상세 → 수정 → 목록으로 이동해도 page, type, keyword를 계속 넘겨야 원래 보던 목록으로 돌아온다.
- 이를 위해 `@ModelAttribute("requestDTO")`와 hidden input을 사용했다.
