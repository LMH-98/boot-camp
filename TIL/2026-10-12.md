# 📋 Spring Boot 게시판 (Board) — JPA 연관관계 + 페이징 + CRUD

> Spring Boot + JPA + Thymeleaf로 만든 게시판.
> 회원(Member) · 게시글(Board) · 댓글(Reply) 세 엔티티의 **연관관계**를 잡고, **JPQL 조인**으로 목록/조회를 처리하고, **페이징 · 등록 · 수정 · 삭제**까지 구현했다.

## 3. 엔티티 & 연관관계

```
Member (1) ──── (N) Board (1) ──── (N) Reply
   email(PK)         bno(PK)              rno(PK)
                     writer → Member      board → Board
```

- 연관관계는 **N쪽(자식)에서만** `@ManyToOne`으로 참조한다 (단방향).
- `Board`는 `Reply`를 모른다 → Board 기준으로 댓글을 가져오려면 JPQL에서 `ON`으로 조인해야 한다.

```java
@Entity
@ToString(exclude = "writer")   // 연관 엔티티는 toString에서 제외 (지연로딩 오류/무한참조 방지)
public class Board extends BaseEntity {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long bno;
    private String title;
    private String content;

    @ManyToOne(fetch = FetchType.LAZY)  // 지연 로딩
    private Member writer;

    // Setter 대신 의미 있는 변경 메서드를 둔다
    public void changeTitle(String title)     { this.title = title; }
    public void changeContent(String content) { this.content = content; }
}
```

### 💡 꼭 알고 넘어갈 것

| 개념 | 핵심 |
|---|---|
| `@MappedSuperclass` + `@EntityListeners(AuditingEntityListener.class)` | 공통 필드(regDate, modDate)를 부모 클래스로 빼고, 저장/수정 시 시간이 **자동** 기록됨. `@EnableJpaAuditing`을 메인 클래스에 꼭 붙여야 동작 |
| `FetchType.EAGER` vs `LAZY` | `@ManyToOne` 기본값은 EAGER(즉시 조인). LAZY는 **실제로 사용할 때** 쿼리를 날림 → 불필요한 조인 방지 |
| LAZY + `@ToString` | toString이 writer를 건드리면 트랜잭션 밖에서 `LazyInitializationException` 발생 → `exclude` 필수 |
| `ddl-auto=update` | 엔티티 변경분만 테이블에 반영 (`create`는 실행할 때마다 테이블 새로 만듦) |

## 4. Repository — JPQL 조인

```java
public interface BoardRepository extends JpaRepository<Board, Long> {

    // ① 연관관계가 있는 경우: b.writer 로 바로 조인
    @Query("select b, w from Board b left join b.writer w where b.bno = :bno")
    Object getBoardWriter(@Param("bno") Long bno);

    // ② 연관관계가 없는 경우(Board → Reply): ON 으로 조인 조건 직접 지정
    @Query("select b, r from Board b left join Reply r on r.board = b where b.bno = :bno")
    List<Object[]> getBoardWithReply(@Param("bno") Long bno);

    // ③ 목록 페이지: 게시글 + 작성자 + 댓글 수
    @Query(value = "select b, w, count(r) from Board b " +
                   "left join b.writer w " +
                   "left join Reply r on r.board = b " +
                   "group by b",
           countQuery = "select count(b) from Board b")
    Page<Object[]> getBoardWithReplyCount(Pageable pageable);
}
```

```java
public interface ReplyRepository extends JpaRepository<Reply, Long> {
    @Modifying   // update / delete JPQL 에는 반드시 필요
    @Query("delete from Reply r where r.board.bno = :bno")
    void deleteByBno(@Param("bno") Long bno);
}
```

### 💡 꼭 알고 넘어갈 것
- 엔티티 여러 개를 `select` 하면 결과는 **`Object[]`** 로 온다 → `arr[0]`=Board, `arr[1]`=Member, `arr[2]`=Long(댓글 수).
- `left join`을 써야 **댓글이 0개인 글도** 목록에 나온다.
- 조인 + `group by`가 들어간 페이징 쿼리는 전체 개수 계산이 복잡해지므로 **`countQuery`를 따로 지정**한다.
- `count()`의 결과 타입은 **`Long`** (int로 캐스팅하면 에러).

## 5. 페이징 — PageRequestDTO / PageResultDTO

### 요청 DTO
```java
public PageRequestDTO() { this.page = 1; this.size = 10; }   // 기본값: 1페이지, 10개

public Pageable getPageable(Sort sort) {
    return PageRequest.of(page - 1, size, sort);   // JPA 페이지는 0부터 시작!
}
```

### 결과 DTO — 화면 하단 페이지 번호 계산
```java
public PageResultDTO(Page<EN> result, Function<EN, DTO> fn) {
    dtoList   = result.stream().map(fn).collect(Collectors.toList()); // 엔티티 → DTO 변환
    totalPage = result.getTotalPages();
    makePageList(result.getPageable());
}

private void makePageList(Pageable pageable) {
    this.page = pageable.getPageNumber() + 1;                  // 다시 1부터로
    int tempEnd = (int)(Math.ceil(page / 10.0)) * 10;          // 가상의 끝 번호
    start = tempEnd - 9;
    prev  = start > 1;
    end   = totalPage > tempEnd ? tempEnd : totalPage;         // 실제 끝 번호
    next  = totalPage > tempEnd;
    pageList = IntStream.rangeClosed(start, end).boxed().collect(Collectors.toList());
}
```

| 현재 페이지 | tempEnd | start | end (총 31페이지일 때) | prev | next |
|---|---|---|---|---|---|
| 3 | 10 | 1 | 10 | false | true |
| 15 | 20 | 11 | 20 | true | true |
| 31 | 40 | 31 | 31 | true | false |

### 💡 꼭 알고 넘어갈 것
- 사용자는 1페이지부터, JPA는 **0페이지부터** → `page - 1` / `+ 1` 변환 위치를 기억할 것.
- `PageResultDTO<DTO, EN>`는 **제네릭 + `Function`** 으로 만들어서 게시판 말고 다른 엔티티에도 재사용 가능.

## 6. Service — DTO ↔ Entity 변환 + CRUD

```java
public interface BoardService {
    Long register(BoardDTO dto);
    PageResultDTO<BoardDTO, Object[]> getList(PageRequestDTO dto);
    BoardDTO get(Long bno);
    void modify(BoardDTO dto);
    void removeWithReplies(Long bno);

    // 변환 메서드는 default 메서드로 인터페이스에 둔다
    default Board dtoToEntity(BoardDTO dto) { ... }
    default BoardDTO entityToDTO(Board board, Member member, Long replyCount) { ... }
}
```

```java
// 목록: Object[] → BoardDTO 변환 함수를 넘겨준다
public PageResultDTO<BoardDTO, Object[]> getList(PageRequestDTO dto) {
    Function<Object[], BoardDTO> fn =
        (en -> entityToDTO((Board) en[0], (Member) en[1], (Long) en[2]));
    Page<Object[]> result =
        boardRepository.getBoardWithReplyCount(dto.getPageable(Sort.by("bno").descending()));
    return new PageResultDTO<>(result, fn);
}

// 삭제: 댓글 먼저 → 게시글 (FK 때문에 순서 중요!)
@Transactional
public void removeWithReplies(Long bno) {
    replyRepository.deleteByBno(bno);
    boardRepository.deleteById(bno);
}

// 수정: 조회 → 변경 메서드 호출
@Transactional
public void modify(BoardDTO dto) {
    Board board = boardRepository.findById(dto.getBno()).get();
    board.changeTitle(dto.getTitle());
    board.changeContent(dto.getContent());
    boardRepository.save(board);
}
```

### 💡 꼭 알고 넘어갈 것
- **Entity는 DB용, DTO는 화면용.** 컨트롤러/뷰에는 DTO만 넘긴다.
- 삭제는 **자식(Reply) → 부모(Board)** 순서. 반대로 하면 외래키 제약조건 에러.
- 두 개 이상의 쿼리가 하나의 작업이면 `@Transactional`로 묶는다 (하나라도 실패하면 전부 롤백).
- `@Transactional` 안에서 조회한 엔티티는 값만 바꿔도 끝날 때 **자동 UPDATE**(변경 감지, Dirty Checking) → `save()`를 안 해도 반영된다.

## 7. Controller

| 메서드 | URL | 하는 일 |
|---|---|---|
| GET | `/board/list` | 목록 + 페이징 |
| GET | `/board/register` | 등록 폼 |
| POST | `/board/register` | 등록 후 목록으로 redirect |
| GET | `/board/read`, `/board/modify` | 조회 / 수정 폼 (같은 메서드로 처리) |
| POST | `/board/modify` | 수정 후 조회 페이지로 redirect |
| POST | `/board/remove` | 삭제 후 목록으로 redirect |

```java
@GetMapping({"/read", "/modify"})   // URL 두 개를 메서드 하나로
public void read(@ModelAttribute("requestDTO") PageRequestDTO pageRequestDTO,
                 @RequestParam("bno") Long bno, Model model) {
    model.addAttribute("dto", boardService.get(bno));
}

@PostMapping("/modify")
public String modify(BoardDTO dto, @ModelAttribute("requestDTO") PageRequestDTO requestDTO,
                     RedirectAttributes redirectAttributes) {
    boardService.modify(dto);
    redirectAttributes.addAttribute("bno", dto.getBno());       // URL 파라미터로 붙음
    redirectAttributes.addAttribute("page", requestDTO.getPage());
    return "redirect:/board/read";
}
```

### 💡 꼭 알고 넘어갈 것
- 반환형이 `void`면 URL과 같은 이름의 뷰(`board/list.html`)를 찾아간다.
- **PRG 패턴**: POST 처리 후에는 `redirect` → 새로고침해도 중복 등록/수정이 안 됨.
- `addAttribute` = URL 쿼리스트링으로 전달 (`?bno=2&page=1`) / `addFlashAttribute` = 한 번만 쓰고 사라지는 값 (등록 완료 메시지 등).
- `@ModelAttribute("requestDTO")` → 페이지 번호를 뷰까지 그대로 전달해서, 목록으로 돌아갈 때 **보던 페이지 유지**.

## 10. 정리하며 알게 된 점 / 주의할 점

- **`getBoardByBno` 쿼리**: `count(r)`를 쓰면서 `group by b`가 빠져 있다. MariaDB에선 돌아가지만 다른 DB에선 에러가 날 수 있으니 `group by b, w`를 붙이는 게 안전하다.
- **application.properties**: `spring.datasource.dbcp2.driver-class-name` → 정식 키는 `spring.datasource.driver-class-name`. (URL로 드라이버를 자동 감지해서 지금은 동작함)
- **BoardDTO**: `@Data`에 이미 `@Getter`, `@Setter`, `@ToString`이 포함돼 있어서 중복 선언은 지워도 된다.
- **`findById().get()`**: 없는 번호면 `NoSuchElementException`. 실무에선 `orElseThrow()`로 의미 있는 예외를 던지자 (register에서 회원 조회할 때처럼).
