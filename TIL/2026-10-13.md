# 📌 board 프로젝트 정리 (Spring Boot + JPA 게시판 + Ajax 댓글)

> 환경: Spring Boot 4.1.1 / Java 21 / MariaDB / Thymeleaf / Lombok / STS
> 핵심 주제: **연관관계가 있는 엔티티(게시글-회원-댓글)를 JPA로 다루고, 댓글은 REST + Ajax로 처리하기**

---

## 1. 전체 구조

```
Controller  →  Service(인터페이스 + Impl)  →  Repository(JpaRepository)  →  DB
   ↑ DTO                 ↕ DTO ↔ Entity 변환              ↑ Entity
```

| 계층 | 클래스 | 역할 |
|---|---|---|
| Entity | `Member`, `Board`, `Reply`, `BaseEntity` | DB 테이블과 매핑 |
| DTO | `BoardDTO`, `ReplyDTO`, `PageRequestDTO`, `PageResultDTO` | 화면과 주고받는 데이터 |
| Repository | `BoardRepository`, `ReplyRepository`, `MemberRepository` | DB 접근 |
| Service | `BoardService(Impl)`, `ReplyService(Impl)` | 비즈니스 로직, DTO↔Entity 변환 |
| Controller | `BoardController`(@Controller), `ReplyController`(@RestController) | 화면 / JSON 응답 |

**왜 Entity를 화면에 바로 쓰지 않고 DTO로 바꾸나?**
- Entity는 DB와 연결된 객체라 화면에서 함부로 바꾸면 안 됨
- 화면에 필요한 데이터(작성자 이름, 댓글 수 등)는 여러 엔티티에 흩어져 있음 → DTO 하나로 모아서 전달

## 2. 엔티티 연관관계 ⭐

```
Member (1) ──── (N) Board (1) ──── (N) Reply
 PK: email          PK: bno            PK: rno
                    writer → Member    board → Board
```

```java
@Entity
public class Board extends BaseEntity {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long bno;
    private String title;
    private String content;

    @ManyToOne(fetch = FetchType.LAZY)   // 게시글 N : 회원 1
    private Member writer;
}
```

- **`@ManyToOne`은 "N쪽"에만 선언**: Board → Member, Reply → Board (단방향 참조)
- Board는 Reply를 모름. Board에서 Reply를 가져오려면 JPQL에서 `on` 조인을 써야 함
- **`FetchType.LAZY`(지연 로딩)**: Board를 조회할 때 Member는 바로 가져오지 않고, `getWriter()`로 실제 사용할 때 쿼리를 날림
  - 장점: 필요 없는 조인을 하지 않음
  - 주의: 트랜잭션이 끝난 뒤에 `board.getWriter()`를 호출하면 **`LazyInitializationException`** 발생 → 테스트에서 `@Transactional`을 붙이거나, 처음부터 조인 쿼리로 가져와야 함
- **`@ToString(exclude = "writer")`**: LAZY 필드를 toString에 포함하면 출력하는 순간 추가 쿼리가 나가거나 예외가 발생함 → 연관 필드는 제외

### BaseEntity + JPA Auditing (등록일/수정일 자동 기록)
```java
@MappedSuperclass                                   // 테이블로 만들지 않고 필드만 상속
@EntityListeners(value = {AuditingEntityListener.class})
public class BaseEntity {
    @CreatedDate  @Column(name = "regDate", updatable = false)
    private LocalDateTime regDate;
    @LastModifiedDate @Column(name = "moddate")
    private LocalDateTime modDate;
}
```
- 메인 클래스에 **`@EnableJpaAuditing`**을 붙여야 동작함 (빠뜨리면 날짜가 null)

## 3. Repository — JPQL과 Object[] 결과 ⭐

```java
// 1) 게시글 + 작성자 (연관관계 있음 → b.writer 로 조인)
@Query("select b, w from Board b left join b.writer w where b.bno = :bno")
Object getBoardWriter(@Param("bno") Long bno);

// 2) 게시글 + 댓글 (Board는 Reply를 모름 → on 절로 조인)
@Query("select b, r from Board b left join Reply r on r.board = b where b.bno = :bno")
List<Object[]> getBoardWithReply(@Param("bno") Long bno);

// 3) 목록: 게시글 + 작성자 + 댓글 수 (페이징)
@Query(value = "select b, w, count(r) from Board b left join b.writer w " +
               "left join Reply r on r.board = b group by b",
       countQuery = "select count(b) from Board b")
Page<Object[]> getBoardWithReplyCount(Pageable pageable);
```

- 여러 엔티티를 한 번에 select하면 결과가 **`Object[]`** → `arr[0]`은 Board, `arr[1]`은 Member, `arr[2]`는 Long(count)
- 조인 방식 두 가지
  - 연관관계가 **있으면**: `left join b.writer w`
  - 연관관계가 **없으면**: `left join Reply r on r.board = b`
- **`countQuery`**: 페이징할 때 전체 개수를 구하는 쿼리. 조인이 복잡하면 따로 지정하는 것이 효율적
- **쿼리 메서드**: `getRepliesByBoardOrderByRno(Board board)` → 메서드 이름만으로 "board로 찾고 rno 순 정렬" 쿼리가 자동 생성됨

### 삭제/수정 쿼리는 `@Modifying` 필수
```java
@Modifying
@Query("delete from Reply r where r.board.bno = :bno")
void deleteByBno(@Param("bno") Long bno);
```

## 4. Service — 게시글 삭제 시 댓글부터 ⭐

```java
@Transactional
public void removeWithReplies(Long bno) {
    replyRepository.deleteByBno(bno);   // ① 댓글 먼저 (FK 때문)
    boardRepository.deleteById(bno);    // ② 게시글
}
```
- Reply가 Board를 FK로 참조하므로 **게시글부터 지우면 FK 제약조건 오류**가 남
- 두 작업이 하나의 단위여야 하므로 **`@Transactional`** (중간에 실패하면 전체 롤백)

### 수정: 엔티티에 setter 대신 change 메서드
```java
@Transactional
public void modify(BoardDTO dto) {
    Board board = boardRepository.findById(dto.getBno()).get();
    board.changeTitle(dto.getTitle());
    board.changeContent(dto.getContent());
    boardRepository.save(board);
}
```
- 엔티티에는 `@Setter`를 열지 않고, **바꿔도 되는 필드만** `changeXxx()`로 열어 둠
- 참고: `@Transactional` 안에서 조회한 엔티티는 값만 바꿔도 트랜잭션이 끝날 때 자동으로 UPDATE가 실행됨(**변경 감지, Dirty Checking**). `save()`를 생략해도 동작함

### DTO ↔ Entity 변환은 인터페이스의 default 메서드로
```java
default BoardDTO entityToDTO(Board board, Member member, Long replyCount) { ... }
```
- `getList()`에서는 `Function<Object[], BoardDTO>`를 만들어 `PageResultDTO`에 넘김
```java
Function<Object[], BoardDTO> fn = (en -> entityToDTO((Board) en[0], (Member) en[1], (Long) en[2]));
```

## 5. 페이징 처리 (PageRequestDTO / PageResultDTO) ⭐

**PageRequestDTO**: 화면 → 서버 (몇 페이지, 몇 개씩)
```java
public Pageable getPageable(Sort sort) {
    return PageRequest.of(page - 1, size, sort);   // JPA 페이지 번호는 0부터!
}
```

**PageResultDTO<DTO, EN>**: 서버 → 화면 (목록 + 페이지 번호 정보)
```java
int tempEnd = (int)(Math.ceil(page / 10.0)) * 10;  // 현재 페이지가 속한 블록의 끝 번호
start = tempEnd - 9;
prev  = start > 1;
end   = totalPage > tempEnd ? tempEnd : totalPage;
next  = totalPage > tempEnd;
```
| 현재 page | tempEnd | start | 
|---|---|---|
| 1~10 | 10 | 1 |
| 11~20 | 20 | 11 |

- 제네릭 `<DTO, EN>`을 써서 **게시판, 영화 등 어떤 프로젝트에서도 재사용** 가능 (mreview에서도 그대로 사용)

## 6. Controller — 화면용 vs REST용

### BoardController (@Controller → HTML 반환)
| URL | 메서드 | 설명 |
|---|---|---|
| `/board/list` | GET | 목록 |
| `/board/register` | GET / POST | 등록 폼 / 등록 처리 |
| `/board/read`, `/board/modify` | GET | 조회 / 수정 폼 (메서드 하나로 처리) |
| `/board/modify` | POST | 수정 처리 |
| `/board/remove` | POST | 삭제 처리 |

- **반환 타입이 `void`**면 URL과 같은 이름의 템플릿을 찾음 (`/board/list` → `templates/board/list.html`)
- **`@GetMapping({"/read", "/modify"})`**: 같은 데이터를 쓰는 두 화면을 메서드 하나로 처리
- **`@ModelAttribute("requestDTO")`**: 받은 페이지 정보를 그대로 화면에 다시 넘김 → 목록으로 돌아갈 때 원래 페이지 유지

### PRG 패턴 (Post → Redirect → Get)
```java
@PostMapping("/register")
public String register(BoardDTO dto, RedirectAttributes ra) {
    Long bno = boardService.register(dto);
    ra.addFlashAttribute("msg", bno);   // 1회용 데이터 (URL에 안 보임)
    return "redirect:/board/list";
}
```
- POST 처리 후 바로 화면을 보여주면 **새로고침할 때 같은 글이 또 등록됨** → 반드시 redirect
- `addFlashAttribute`: 일회성, URL에 노출 안 됨
- `addAttribute`: URL 쿼리 스트링으로 붙음 (`?bno=2&page=1`) → 수정 후 read 페이지로 돌아갈 때 사용

### ReplyController (@RestController → JSON 반환) ⭐
| URL | HTTP 메서드 | 설명 |
|---|---|---|
| `/replies/board/{bno}` | GET | 특정 게시글의 댓글 목록 |
| `/replies` | POST | 댓글 등록 |
| `/replies/{rno}` | PUT | 댓글 수정 |
| `/replies/{rno}` | DELETE | 댓글 삭제 |

```java
@PostMapping("")
public ResponseEntity<Long> register(@RequestBody ReplyDTO replyDTO) {
    Long rno = replyService.register(replyDTO);
    return new ResponseEntity<>(rno, HttpStatus.OK);
}
```
- **REST 방식**: URL은 "자원"(replies)을 표현하고, "행위"는 HTTP 메서드(GET/POST/PUT/DELETE)로 구분
- **`@PathVariable`**: URL 경로의 값 (`/replies/5` → rno=5)
- **`@RequestBody`**: 요청 본문의 JSON → 자바 객체로 변환 (Jackson이 처리)
- **`ResponseEntity`**: 데이터 + HTTP 상태코드를 함께 반환

## 7. 화면 (Thymeleaf + jQuery Ajax)

### 레이아웃 적용
```html
<th:block th:replace="~{layout/basic :: setContent(~{this::content})}">
    <th:block th:fragment="content"> ... 페이지 내용 ... </th:block>
</th:block>
```
- `basic.html`에 공통 틀(사이드바, 네비게이션)을 두고, 각 페이지의 `content` 조각만 끼워 넣음

### 자주 쓴 Thymeleaf 문법
| 문법 | 예시 |
|---|---|
| 반복 | `th:each="dto : ${result.dtoList}"` |
| 링크 + 파라미터 | `th:href="@{/board/read(bno=${dto.bno}, page=${result.page})}"` |
| 인라인 출력 | `[[${dto.title}]]` |
| 날짜 포맷 | `${#temporals.format(dto.regDate, 'yyyy/MM/dd')}` |
| 문자열 결합 | `th:value="|${dto.writerName} (${dto.writerEmail})|"` |
| JS에서 서버 값 사용 | `<script th:inline="javascript">` 안에서 `const bno = [[${dto.bno}]];` |

### Ajax로 댓글 처리
```javascript
// 조회
$.getJSON('/replies/board/' + bno, function(arr){ ... });

// 등록 (JSON 전송)
$.ajax({
    url: '/replies',
    method: 'post',
    data: JSON.stringify(reply),                       // 객체 → JSON 문자열
    contentType: 'application/json; charset=utf-8',    // @RequestBody 받으려면 필수
    success: function(data){ loadJSONData(); }
});
```
- **동적으로 만든 요소에는 이벤트 위임**을 써야 함
```javascript
$('.replyList').on('click', '.card-body', function(){ ... });
// $('.card-body').click(...) 은 나중에 추가된 댓글에는 동작하지 않음
```

## 8. 테스트 코드 활용
- `@SpringBootTest` + `@Autowired`로 Repository/Service를 바로 테스트
- `IntStream.rangeClosed(1, 100)`으로 더미 데이터 생성
- 테스트에서 `@Transactional`을 쓰면 **기본은 롤백** → 실제로 DB에 반영하려면 **`@Commit`** 추가
- 이미 실행한 테스트는 `//@Test`로 주석 처리해서 중복 실행 방지

## 9. ⚠️ 주의할 점 / 코드에서 발견한 문제

1. **댓글 작성자 필드명 불일치 (실제 버그)**
   - `Reply` 엔티티: `replyer` / `ReplyDTO`: **`replier`** / JS: `replyer`
   - JSON 키(`replyer`)와 DTO 필드명(`replier`)이 달라서 **작성자가 null로 저장**되고, 목록에는 `undefined`로 표시됨
   - 👉 **JSON 키 = DTO 필드명**이어야 `@RequestBody` 바인딩이 됨. 이름을 하나로 통일할 것
2. `ReplyService.entityToDTO()`에 `bno`가 빠져 있음 (지금 화면에서는 안 써서 문제가 드러나지 않을 뿐)
3. `application.properties`의 `spring.datasource.dbcp2.driver-class-name`은 정확히는 `spring.datasource.driver-class-name`. 지금은 URL을 보고 드라이버를 자동으로 찾아서 동작하는 것
4. `findById(...).get()`은 값이 없으면 예외 → 실무에서는 `orElseThrow()` 사용 권장 (`register()`에서는 이미 이렇게 처리함)
