## 1. 엔티티 설계 — M:N 관계 풀기 ⭐⭐

"회원은 여러 영화에 리뷰를 쓰고, 영화에는 여러 회원의 리뷰가 달린다" → **다대다(M:N)**

관계형 DB는 M:N을 직접 표현할 수 없으므로 **중간에 매핑 테이블(Review)**을 두고 1:N 두 개로 나눔

```
Movie (1) ─── (N) Review (N) ─── (1) Member
  │                (평점, 내용)
  └── (1) ─── (N) MovieImage
```

```java
@Entity
public class Review extends BaseEntity {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long reviewnum;

    @ManyToOne(fetch = FetchType.LAZY) private Movie movie;
    @ManyToOne(fetch = FetchType.LAZY) private Member member;

    private int grade;    // 평점
    private String text;  // 리뷰 내용
}
```
- 매핑 테이블은 단순한 연결만 하는 게 아니라 **평점·내용 같은 자체 데이터**를 가질 수 있음
- 매핑 테이블은 **양쪽 테이블에 데이터가 먼저 있어야** 만들 수 있음 (영화, 회원 → 리뷰 순서)

| 엔티티 | PK | 특징 |
|---|---|---|
| `Movie` | mno | 제목만 가짐 |
| `MovieImage` | ino | uuid, imgName, path + `@ManyToOne Movie` |
| `Member` | mid (자동증가) | `@Table(name = "m_member")` → board의 member 테이블과 이름 충돌 방지 |
| `Review` | reviewnum | Movie, Member 참조 + grade, text |

## 2. Repository — 집계 쿼리 ⭐

### 영화 목록: 영화 + 대표 이미지 + 평균 평점 + 리뷰 수
```java
@Query("select m, mi, avg(coalesce(r.grade, 0)), count(distinct r) from Movie m " +
       "left outer join MovieImage mi on mi.movie = m " +
       "left outer join Review r on r.movie = m group by m")
Page<Object[]> getListPage(Pageable pageable);
```
- **`coalesce(r.grade, 0)`**: 리뷰가 없어 grade가 null이면 0으로 처리
- **`count(distinct r)`**: 이미지와 리뷰를 동시에 조인하면 행이 (이미지 수 × 리뷰 수)만큼 늘어남 → `distinct`로 중복을 제거해야 정확한 리뷰 수가 나옴
- `group by m` → 영화 하나당 한 줄

### 영화 상세: 모든 이미지 + 평균 + 리뷰 수
```java
@Query("select m, mi, avg(coalesce(r.grade, 0)), count(distinct r) from Movie m " +
       "left outer join MovieImage mi on mi.movie = m " +
       "left outer join Review r on r.movie = m " +
       "where m.mno = :mno group by mi")
List<Object[]> getMovieWithAll(@Param("mno") Long mno);
```
- 목록과 달리 **`group by mi`** → 이미지 개수만큼 행이 나옴 (Service에서 이미지만 모아 List로 만듦)

### @EntityGraph — LAZY를 그때그때 EAGER로 ⭐
```java
@EntityGraph(attributePaths = {"member"}, type = EntityGraphType.FETCH)
List<Review> findByMovie(Movie movie);
```
- Review의 member는 LAZY인데, 리뷰 목록에서는 회원 닉네임이 꼭 필요함
- `@EntityGraph`로 **이 메서드에서만 member를 조인해서 한 번에** 가져옴
  - 없으면 `review.getMember().getEmail()` 호출 시 `LazyInitializationException` 또는 리뷰 수만큼 추가 쿼리(**N+1 문제**)
- `FETCH`: 지정한 속성만 EAGER, 나머지는 LAZY / `LOAD`: 지정한 속성만 EAGER, 나머지는 엔티티에 선언된 방식대로

### 회원 삭제 시 리뷰도 삭제
```java
@Modifying
@Query("delete from Review mr where mr.member = :member")
void deleteByMember(@Param("member") Member member);
```
- board의 "댓글 먼저 삭제"와 같은 원리: **FK를 가진 쪽(Review)부터 삭제** → 그다음 Member
- 메서드 이름만으로 만든 `deleteByMember`는 한 건씩 delete가 나가므로, `@Query`로 한 번에 삭제하는 게 효율적

## 3. 파일 업로드 ⭐⭐

### 설정 (application.properties)
```properties
spring.servlet.multipart.enabled=true
spring.servlet.multipart.location=C:\\upload
spring.servlet.multipart.max-file-size=10MB      # 파일 1개 최대
spring.servlet.multipart.max-request-size=30MB   # 요청 전체 최대
com.fullstack.upload.path=C:\\upload             # 직접 정의한 값 → @Value로 주입
```
```java
@Value("${com.fullstack.upload.path}")
private String uploadPath;
```

### 업로드 처리 흐름 (`POST /uploadAjax`)
```
① 이미지인지 확인 (contentType이 image로 시작하는지)
② 원본 파일명 추출
③ 날짜 폴더 생성 (2026/10/15)
④ UUID_원본파일명 으로 저장
⑤ 썸네일 생성: s_UUID_원본파일명 (100x100)
⑥ 결과(파일명, uuid, 폴더경로)를 JSON으로 응답
```

| 포인트 | 이유 |
|---|---|
| **UUID** 붙이기 | 같은 이름의 파일이 업로드돼도 덮어쓰지 않도록 |
| **날짜별 폴더** | 한 폴더에 파일이 너무 많이 쌓이면 느려짐 |
| **썸네일**(`s_` 접두어) | 목록에서 원본 대신 작은 이미지를 써서 트래픽 절약 |
| **이미지 검증** | 실행 파일 등 위험한 파일 업로드 차단 |

```java
uploadFile.transferTo(savePath);                                       // 원본 저장
Thumbnailator.createThumbnail(savePath.toFile(), thumbnailFile, 100, 100); // 썸네일
```

### 화면 쪽: FormData로 Ajax 전송
```javascript
var formData = new FormData();
formData.append("uploadFiles", files[i]);   // 서버의 @RequestParam("uploadFiles")와 이름 일치

$.ajax({
    url: '/uploadAjax',
    processData: false,   // ⭐ 파일 전송 시 필수: 데이터를 문자열로 바꾸지 않음
    contentType: false,   // ⭐ 필수: multipart/form-data 경계값을 브라우저가 자동 설정
    data: formData,
    type: 'POST'
});
```

### 이미지 보여주기 (`GET /display?fileName=...`)
- 업로드 폴더(C:\upload)는 웹 경로가 아니므로 브라우저가 직접 접근할 수 없음
- → **컨트롤러가 파일을 `byte[]`로 읽어 응답**하고, `Content-Type` 헤더로 이미지임을 알려줌
```java
header.add("Content-Type", Files.probeContentType(file.toPath()));
return new ResponseEntity<>(FileCopyUtils.copyToByteArray(file), header, HttpStatus.OK);
```

### URL 인코딩 / 디코딩
- 파일 경로에 한글, 공백, `\`가 들어가므로 URL로 보낼 때 **`URLEncoder.encode()`** (DTO의 `getImageURL()`, `getThumbnailURL()`)
- 서버에서 받을 때 **`URLDecoder.decode()`**
- `getImageURL()` 같은 getter는 필드가 없어도 **JSON 변환 시 `imageURL` 속성으로 포함됨** → JS에서 `obj.imageURL`로 사용

### 파일 삭제 (`POST /removeFile`)
- 원본과 썸네일(`s_` + 파일명)을 **둘 다** 삭제

## 4. 영화 등록 — 이미지 정보를 폼에 담아 보내기 ⭐

### 흐름
```
파일 선택 → 즉시 Ajax 업로드 → 썸네일 미리보기
→ Submit 클릭 시 업로드 결과를 hidden input으로 만들어 폼 전송
```

### List<DTO> 바인딩
```javascript
str += "<input type='hidden' name='imageDTOList[" + i + "].imgName' value='...'>";
str += "<input type='hidden' name='imageDTOList[" + i + "].path' value='...'>";
str += "<input type='hidden' name='imageDTOList[" + i + "].uuid' value='...'>";
```
- **`name="리스트필드명[인덱스].필드"`** 형식이면 스프링이 `MovieDTO.imageDTOList`에 자동으로 채워줌

### MovieDTO
```java
@Builder.Default
private List<MovieImageDTO> imageDTOList = new ArrayList<>();
```
- **`@Builder`를 쓰면 필드 초기값이 무시됨** → `@Builder.Default`를 붙여야 빌더로 만들어도 빈 리스트가 유지됨

### Service: 엔티티 2종류를 Map으로 반환
```java
default Map<String, Object> dtoToEntity(MovieDTO movieDTO) {
    entityMap.put("movie", movie);
    entityMap.put("imgList", movieImageList);
    return entityMap;
}
```
```java
@Transactional
public Long register(MovieDTO movieDTO) {
    movieRepository.save(movie);                         // ① 영화 먼저
    movieImageList.forEach(movieImageRepository::save);  // ② 이미지
    return movie.getMno();
}
```
- DTO 하나가 엔티티 여러 개(Movie + MovieImage들)로 나뉨 → Map에 담아서 반환
- 이미지가 영화를 FK로 참조하므로 **영화부터 저장**

## 5. 목록 / 상세 화면

- 목록: `getListPage()` 결과 → `entityToDTO()`로 변환. 이미지는 대표 1장만 `Arrays.asList(...)`로 감싸서 전달
- 목록 화면의 썸네일 출력
```html
<img th:if="${dto.imageDTOList.size() > 0 && dto.imageDTOList[0].path != null}"
     th:src="|/display?fileName=${dto.imageDTOList[0].getThumbnailURL()}|">
```
  - 이미지가 없는 영화도 left join 때문에 null 이미지가 한 장 들어오므로 **`path != null` 체크**가 필요
- 상세: `getMovieWithAll()` 결과를 돌면서 이미지만 리스트로 모으고, 영화/평균/리뷰 수는 첫 행(`result.get(0)`)에서 꺼냄
- 페이지 번호 출력: `PageResultDTO`의 `prev`, `pageList`, `next` 사용 (board에서 만든 그대로)

## 7. ⚠️ 주의할 점 / 코드에서 발견한 문제

1. **`ReviewService` 인터페이스에 `@Service`가 붙어 있음**
   - `@Service`는 **구현 클래스(`ReviewServiceImpl`)**에 붙여야 함. 인터페이스에 붙이면 빈이 만들어지지 않음
   - 지금 `ReviewServiceImpl`에는 `@Service`, `@RequiredArgsConstructor`, `ReviewRepository` 필드가 모두 없음 → 구현할 때 추가
2. **이미지 없이 영화를 등록하면 NullPointerException**
   - 이미지가 없으면 `dtoToEntity()`가 `"imgList"`를 Map에 넣지 않음 → `register()`에서 `movieImageList.forEach()` 호출 시 NPE
   - 👉 `if (movieImageList != null)` 체크 또는 처음부터 빈 리스트를 넣어 두기
3. `getMovie()`에서 존재하지 않는 mno로 조회하면 `result.get(0)`에서 `IndexOutOfBoundsException`
4. 목록 쿼리에서 `group by m`인데 `mi`(이미지)를 select하고 있음 → 어떤 이미지가 대표로 나올지 보장되지 않음 (MariaDB는 허용하지만 다른 DB에서는 에러가 날 수 있음)
5. 업로드 경로가 `C:\\upload`로 고정 → 다른 PC/OS에서 실행하면 경로 수정이 필요

## ✅ 한 줄 요약 (현재까지)
> **M:N은 매핑 테이블(Review)로 풀고 → 집계 쿼리(avg, count distinct)로 목록 구성 → 이미지는 UUID + 날짜 폴더 + 썸네일로 저장하고 컨트롤러가 byte[]로 보여줌 → 다음은 리뷰 REST 처리**
