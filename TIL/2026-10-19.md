## 0. 프로젝트 구조와 실행 흐름

```bash
npx create-react-app 프로젝트명
cd 프로젝트명
npm start          # http://localhost:3000
```

```
public/index.html   <div id="root"></div>        ← 빈 틀
src/index.js        root.render(<App />)         ← #root 안에 App을 그린다
src/App.js          <Hello />, <Counter /> ...   ← 컴포넌트를 조립한다
```

- `<React.StrictMode>`(index.js): 개발 중 실수를 잡아 주는 검사용 래퍼. 개발 모드에서는 컴포넌트 함수를 일부러 한 번 더 실행하기 때문에, 컴포넌트 본문에 찍은 `console.log`가 두 번 보일 수 있다. 배포 빌드에는 영향 없음.

([Sunsetting Create React App](https://react.dev/blog/2025/02/14/sunsetting-create-react-app))

## 1. 컴포넌트 (Hello.js)

- 컴포넌트 = **JSX를 return하는 함수**. 화면의 한 조각을 맡는다.
- 이름은 반드시 **대문자로 시작**한다. 소문자(`<hello />`)는 HTML 태그로 인식된다.
- 만든 파일에서 `export default`로 내보내고, 쓰는 파일에서 `import`한다.

```jsx
// Hello.js
function Hello({ color, name, isSpecial }) {
  return (
    <div style={{ color: color }}>
      {isSpecial && <b>*</b>}
      안녕하세요. {name}
    </div>
  );
}
export default Hello;
```

```jsx
// App.js
import Hello from './Hello';
```

### JSX 기본 규칙

| 규칙 | 예시 |
|---|---|
| JS 값·표현식은 `{ }` 안에 쓴다 | `{name}` |
| `style`은 문자열이 아니라 **객체**로 준다 | `style={{ color: color }}` — 바깥 `{}`는 "여기부터 JS", 안쪽 `{}`는 객체 |
| CSS 속성명은 camelCase | `background-color` → `backgroundColor` |
| return은 **하나의 태그로 감싼다** | `<div>...</div>` (div가 필요 없으면 `<>...</>`) |
| JSX 안의 주석은 `{/* */}` | `{/* <Counter /> */}` |

## 2. props — 컴포넌트에 넘기는 값

- **props** = properties의 줄임말. 컴포넌트를 부를 때 넘겨주는 **파라미터**다.
- **부모 → 자식 한 방향**으로만 전달되고, 자식은 받은 props를 **읽기만** 한다(수정 X).

```jsx
<Hello name="react" color="red" isSpecial={true} />
<Hello color="pink" />
```

- 문자열은 `"..."`, 그 외 값(true, 숫자, 변수)은 `{ }`로 넘긴다.
- 받는 쪽은 비구조화 할당으로 바로 꺼내 쓴다.

```jsx
// 둘 다 같은 뜻
function Hello(props) {
  return <div>{props.name}</div>;
}
function Hello({ name }) {
  return <div>{name}</div>;
}
```

- 넘기지 않은 props는 `undefined` → 두 번째 Hello는 이름 없이 "안녕하세요."만 출력된다.

### 조건부 렌더링 `&&`

```jsx
{isSpecial && <b>*</b>}
```

- `isSpecial`이 true면 `<b>*</b>`를 그리고, false·undefined면 아무것도 그리지 않는다.
- JSX의 `{ }` 안에는 `if`문을 쓸 수 없어서 `&&`나 삼항 연산자(`? :`)를 쓴다.

## 3. children — 태그 사이의 내용 (Wrapper.js)

- 컴포넌트 태그 **사이에** 넣은 내용은 `children`이라는 props로 들어온다.

```jsx
// App.js
<Wrapper>
  <Hello name="react" color="red" isSpecial={true} />
  <Hello color="pink" />
</Wrapper>
```

```jsx
// Wrapper.js
function Wrapper({ children }) {
  const style = {
    border: '2px solid black',
    padding: '16px'
  };
  return <div style={style}>{children}</div>;
}
```

- Wrapper가 `{children}`을 그려 줘야 안의 Hello들이 보인다. **빼먹으면 테두리만 남고 내용이 사라진다.**
- 테두리·카드·레이아웃처럼 "감싸는 틀"을 재사용할 때 쓴다.
- style 객체를 변수로 빼 두면 `style={style}`처럼 중괄호를 한 겹만 쓴다.

## 4. useState와 이벤트 (Counter.js)

### 왜 state가 필요한가

- 일반 변수(`let number = 0; number++`)는 값이 바뀌어도 **화면이 다시 그려지지 않는다.**
- 화면에 반영돼야 하는 값은 `useState`로 만든다. setter로 값을 바꾸면 React가 화면을 **다시 그린다**(리렌더링).

```jsx
import React, { useState } from 'react';

const [number, setNumber] = useState(0);
// number    : 현재 값
// setNumber : 값을 바꾸는 함수 (setter)
// 0         : 초기값
```

- `useState(초기값)`은 `[현재 값, 값을 바꾸는 함수]` **배열**을 돌려준다 → 배열 비구조화로 받는다.
- Java로 치면 **필드 + setter**. 다른 점은 setter를 부르면 화면이 다시 그려진다는 것.
- 값은 **반드시 setter로만** 바꾼다. (`number = 5` ❌)

### 리렌더링 = 컴포넌트 함수가 다시 실행되는 것

1. `setNumber(1)` 호출
2. React가 `Counter()` 함수를 **처음부터 다시 실행**
3. 이번에는 `useState(0)`이 0이 아니라 저장해 둔 1을 돌려줌 (초기값은 처음 한 번만 쓰인다) → 새 화면

- 그래서 `number`가 `const`인데도 화면 값이 바뀐다. 변수를 고치는 게 아니라, 함수가 다시 실행될 때 새 값을 받는 것이다.
- 같은 이유로 setter를 부른 **직후**, 같은 함수 안에서 `number`를 찍어 보면 아직 **이전 값**이다.

### 이벤트 연결

```jsx
const onIncrease = () => {
  setNumber(prevNumber => prevNumber + 1);
};
const onDecrease = () => {
  setNumber(number - 1);
};

<button onClick={onIncrease}>+1</button>
<button onClick={onDecrease}>-1</button>
```

| ✅ | ❌ | 이유 |
|---|---|---|
| `onClick={onIncrease}` | `onClick={onIncrease()}` | `()`를 붙이면 클릭할 때가 아니라 **렌더링될 때 바로 실행**된다. 안에서 setter를 부르면 무한 렌더링 에러(`Too many re-renders`) |
| `onClick` | `onclick` | 이벤트 이름은 camelCase |

### setter에 "값" vs "함수" (함수형 업데이트)

오늘 코드의 +1과 -1은 서로 다른 방식으로 작성되어 있다.

```jsx
setNumber(number - 1);                    // 새 값을 직접 전달
setNumber(prevNumber => prevNumber + 1);  // 함수를 전달 (함수형 업데이트)
```

버튼을 한 번 누를 때 한 번만 바꾸면 결과가 같다. 차이는 **한 번에 여러 번** 바꿀 때 드러난다.

```jsx
// number가 0일 때

setNumber(number + 1);
setNumber(number + 1);
// → 1  (두 줄 모두 지금 화면의 number = 0 기준으로 계산)

setNumber(prev => prev + 1);
setNumber(prev => prev + 1);
// → 2  (React가 직전 결과를 prev로 넘겨줌)
```

→ **이전 값을 기준으로 바꿀 때는 함수형 업데이트**가 안전하다.

## 5. 여러 개의 input 상태 관리 (InputSample.js)

### input은 `value` + `onChange` 세트

- `value={state}`로 입력창을 state에 묶고, `onChange`에서 state를 바꾼다. 화면에 보이는 값 = state 값 (**제어 컴포넌트**)
- 그래서 초기화 버튼에서 **state만 `''`로 바꿔도 입력창이 비워진다.**
- `value`만 주고 `onChange`가 없으면 입력이 안 된다. (읽기 전용이 됨)

### input이 여러 개면 → 객체 state 하나로

```jsx
const [inputs, setInputs] = useState({
  name: '',
  nickname: ''
});
const { name, nickname } = inputs;   // 비구조화 할당으로 꺼내 쓰기

const onChange = (e) => {
  const { value, name } = e.target;  // 지금 입력 중인 input의 name, value
  setInputs({
    ...inputs,      // ① 기존 값 전부 복사
    [name]: value   // ② 바뀐 칸만 덮어쓰기
  });
};

const onReset = () => {
  setInputs({ name: '', nickname: '' });
};
```

```jsx
<input name="name" placeholder="이름" onChange={onChange} value={name} />
<input name="nickname" placeholder="닉네임" onChange={onChange} value={nickname} />
<button onClick={onReset}>초기화</button>
```

**핵심 3가지**

1. **input의 `name` 속성 = state의 key**로 맞춘다. 그래야 `onChange` 하나로 모든 input을 처리할 수 있다.
2. **`e.target`** = 이벤트가 일어난 input 태그. 여기서 `name`과 `value`를 꺼낸다.
   - `onChange` 안의 `name`은 위에서 꺼낸 `inputs.name`이 아니라 `e.target.name`이다. (함수 안에서 같은 이름으로 새로 선언했기 때문)
3. **`[name]: value`** (계산된 속성명) — 대괄호를 써야 변수 `name`에 **들어 있는 값**(`"name"` 또는 `"nickname"`)이 key가 된다.
   - 대괄호 없이 `name: value`라고 쓰면 key가 항상 글자 그대로 `"name"`이 돼서, 닉네임 칸에 입력해도 이름 값이 바뀐다.

### 왜 `...inputs`로 복사해야 하나 (불변성)

```jsx
// ❌ 기존 객체를 직접 수정
inputs[name] = value;
setInputs(inputs);              // 같은 객체 → React가 "안 바뀌었다"고 보고 화면을 안 바꾼다

// ❌ 복사 없이 새 객체
setInputs({ [name]: value });   // 다른 칸 값이 state에서 사라진다 (undefined)

// ✅ 기존 값을 복사한 "새 객체"로 교체
setInputs({ ...inputs, [name]: value });
```

- React는 state가 바뀌었는지를 **다른 객체인지**로 판단한다.
- 그래서 객체·배열 state는 직접 고치지 말고 **새로 만들어서** setter에 넘긴다. 이걸 **불변성을 지킨다**고 한다.

## 오늘의 핵심 체크리스트

- [ ] 컴포넌트는 대문자로 시작하는 함수, `export default` → `import`
- [ ] props는 부모 → 자식으로 넘기는 읽기 전용 값, `{ }`로 꺼내 받는다
- [ ] 태그 사이에 넣은 내용은 `children`으로 받는다
- [ ] 화면에 반영할 값은 `useState`, 바꿀 때는 반드시 setter로
- [ ] setter 호출 → 컴포넌트 함수가 다시 실행된다(리렌더링)
- [ ] `onClick={함수}` — `()`를 붙이지 않는다
- [ ] 이전 값 기준으로 바꿀 때는 `setX(prev => ...)`
- [ ] input은 `value` + `onChange` 세트
- [ ] 객체 state는 `{ ...기존, [key]: 값 }`처럼 새 객체를 만들어 교체한다
